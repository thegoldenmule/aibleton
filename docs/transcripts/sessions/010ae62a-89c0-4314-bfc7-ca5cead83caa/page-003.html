OAuth login file (recommended). Log in locally, then copy the file into mate's data directory on the box:

The deploy now sets SPLICE_OAUTH_FILE to that path. Keep the file owned by the service user, since mate rewrites it when it refreshes the token.

Plain bearer token. Add a line to /srv/aibleton/secrets.env on the box and restart mate:

SPLICE_MCP_TOKEN=...

That file is loaded by the systemd unit and deploys never overwrite it. When the token is set, the OAuth file is ignored.

MATE_SPLICE is now auto on the box, so with neither credential it keeps using fixtures. Check https://aibleton.thegoldenmule.com/mate/adapters to confirm Splice reports live.
