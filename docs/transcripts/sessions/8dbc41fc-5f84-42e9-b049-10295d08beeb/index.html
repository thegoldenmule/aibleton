/** `Promise.all` with at most `limit` mappers in flight. Order preserved; the first rejection rejects the whole call. */
export async function mapLimit&lt;T, R&gt;(items: readonly T[], limit: number, fn: (item: T, index: number) =&gt; Promise&lt;R&gt;): Promise&lt;R[]&gt; {
  const results = new Array&lt;R&gt;(items.length);
  let next = 0;
  const worker = async () =&gt; {
    while (next &lt; items.length) { const i = next++; results[i] = await fn(items[i]!, i); }
  };
  await Promise.all(Array.from({ length: Math.max(1, Math.min(limit, items.length)) }, worker));
  return results;
}

Storage and refresh

One JSON file, .mate/splice-oauth.json (gitignored), written atomically via temp-file rename with mode 0600. It holds client (the dynamic registration), clientRedirectUrl (the redirect URL we registered with; if SPLICE_OAUTH_CALLBACK_PORT changes the registration is treated as missing and redone), tokens, and pending (PKCE verifier + state, deleted once tokens land). It is zod-validated on read; a missing or corrupt file means "never logged in" and the next save replaces it.

Refresh is the SDK's and is reactive only: the access token is sent on every request, and on a 401 the SDK exchanges the refresh token, calls saveTokens, and retries. A rejected refresh (invalid_grant) hits invalidateCredentials("tokens"), which drops the tokens from the file, so the next startup reports "not logged in" without any network. SPLICE_MCP_TOKEN still works as a plain bearer override and makes the OAuth file irrelevant.

SDK details worked around

  • A transport whose connect failed cannot be restarted (start() throws on a set abort controller and close() never clears it), but it is the only object holding the 401's resource-metadata URL and scope. So finishAuth runs on the dead transport and McpConnection.connect() then builds a fresh one that picks up the saved tokens.
  • Without saved tokens the SDK performs discovery plus dynamic client registration before redirecting, on every attempt. createSplicePort therefore short-circuits with the "not logged in" reason when the file has no tokens, so an unlogged-in mate does not register a new client at each startup.
  • The SDK never verifies state; it only passes provider.state() into the URL. parseCallback checks it against the state persisted beside the verifier.
  • A 401 that follows a just-completed auth surfaces as StreamableHTTPError(401), not UnauthorizedError; both map to the login reason.
  • The SDK's schemas are zod/v4 while mate uses the v3 API from zod@3.25, so the file schema is mate's own (.passthrough() on the SDK-owned objects) and values are cast to the SDK types at the boundary.
